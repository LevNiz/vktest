# Green Button Tapper

Python-скрипт, который запускает Android-приложение на телефоне, подключённом по ADB,
находит на экране **зелёную кнопку** и нажимает на неё. Если за 10 секунд кнопка не появилась,
скрипт выводит сообщение об этом.

Автоматизаторы (Appium, uiautomator, Espresso и т. п.) не используются. Скрипт берёт скриншот
через `adb exec-out screencap`, ищет кнопку средствами компьютерного зрения (OpenCV) и нажимает
через `adb shell input tap`.

## Требования

- **Python 3.12**
- **adb** из [Android SDK Platform-Tools](https://developer.android.com/tools/releases/platform-tools), доступный в `PATH`
  (или путь к нему через `--adb`)
- Телефон или эмулятор с включённой отладкой по USB; в `adb devices` у него должен быть статус `device`

Python-зависимости (`requirements.txt`):

| Пакет                    | Зачем                                                    |
|--------------------------|----------------------------------------------------------|
| `opencv-python-headless` | декодирование скриншота, HSV-маска, поиск контуров       |
| `numpy`                  | работа с изображением как с массивом (нужен для OpenCV)  |

Для тестов дополнительно нужен `pytest` (`requirements-dev.txt`).

## Установка

```bash
python3.12 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## Запуск

```bash
python main.py com.example.app
```

Можно запускать и как модуль: `python -m green_button_tapper com.example.app`.

Опции:

| Опция                  | Описание                                                                 |
|------------------------|--------------------------------------------------------------------------|
| `package`              | имя пакета приложения (обязательно)                                      |
| `-s, --serial SERIAL`  | серийный номер устройства, если подключено несколько                     |
| `-t, --timeout SEC`    | общий таймаут, по умолчанию **10** с                                     |
| `--restart`            | перед запуском сделать `am force-stop`, чтобы открыть начальный экран    |
| `--adb PATH`           | путь к `adb`, если его нет в `PATH`                                      |
| `--debug-image FILE`   | сохранить последний скриншот с подсвеченной кнопкой (для отладки)        |
| `-v, --verbose`        | подробный лог: команды adb, попытки, число кандидатов                    |

Пример вывода:

```
$ python main.py com.example.app
Приложение com.example.app запущено, ищу зелёную кнопку...
Зелёная кнопка найдена (840x154 px) и нажата в точке (540, 1630).

$ python main.py com.android.settings
Приложение com.android.settings запущено, ищу зелёную кнопку...
Зелёная кнопка не найдена в приложении com.android.settings за 10 c.
```

### Коды возврата

| Код | Значение                                                                 |
|-----|--------------------------------------------------------------------------|
| 0   | кнопка найдена и нажата                                                  |
| 1   | кнопка не найдена за отведённое время                                    |
| 2   | неверные аргументы (например, некорректное имя пакета)                   |
| 3   | проблема окружения: нет adb, нет устройства, пакет не установлен и т. п. |

## Как это работает

1. **Проверки.** Устройство доступно (`adb get-state`), пакет установлен (`pm path`).
   Имя пакета проверяется регулярным выражением, поэтому в shell-команды не может попасть
   произвольный текст.
2. **Запуск приложения.** Launcher-activity определяется через
   `cmd package resolve-activity` и запускается через `am start -n`. На старых Android, где
   `cmd package` нет, используется запасной вариант `monkey -p <pkg> -c LAUNCHER 1`.
3. **Ожидание и поиск** (цикл до истечения таймаута, шаг 0.3 с):
   - через `dumpsys window` проверяется, что на переднем плане уже наше приложение, а не лаунчер.
     Иначе зелёная иконка на рабочем столе дала бы ложное срабатывание;
   - снимается скриншот `adb exec-out screencap -p`;
   - кадр переводится в HSV, и в маску попадают пиксели с зелёным оттенком (H 70°–170°)
     и достаточными насыщенностью и яркостью. Белый, серый, чёрный и бледные оттенки отсекаются;
   - морфологией маска очищается от шума, а промежутки (сглаживание краёв, текст на кнопке)
     закрываются;
   - по внешним контурам остаются только области, похожие на кнопку:
     - не меньше 4 % ширины и 1.5 % высоты экрана (так отсекаются иконки и индикаторы статус-бара);
     - не больше 40 % площади экрана (так отсекается зелёный фон);
     - внутри рамки не меньше 50 % зелёных пикселей (так отсекаются контуры и разреженный «мусор»);
     - соотношение сторон не больше 15:1 (так отсекаются линии и разделители);
   - если подходит несколько областей, выбирается самая большая. Нажатие идёт в её центр
     (`input tap x y`). Координаты скриншота совпадают с координатами экрана, поэтому
     пересчёт под разрешение и DPI не нужен.
4. **Таймаут.** Общий бюджет времени (10 с) отсчитывается с начала работы скрипта и включает
   запуск приложения. Таймаут каждой команды adb ограничен оставшимся временем, поэтому
   зависший `adb` не растянет выполнение. Временные ошибки (например, screencap во время
   анимации перехода) не прерывают поиск: скрипт просто делает следующую попытку.

Пороги собраны в `DetectorConfig` ([detector.py](green_button_tapper/detector.py)) и легко
меняются под конкретное приложение.

## Структура проекта

```
main.py                         точка входа: python main.py <package>
green_button_tapper/
  adb.py                        обёртка над adb: запуск, скриншот, тап, foreground
  detector.py                   поиск зелёной кнопки на изображении (OpenCV)
  cli.py                        аргументы, цикл ожидания с таймаутом, коды возврата
tests/
  test_detector.py              детектор на синтетических экранах
  test_adb.py                   разбор вывода adb, ошибки, fallback-запуск (с моками)
  test_cli.py                   цикл ожидания и таймаут на фейковом устройстве и часах
  test_e2e.py, fake_adb.py      запуск main.py как отдельного процесса против фейкового adb
requirements.txt                зависимости
requirements-dev.txt            зависимости для тестов
```

## Тесты

Для тестов телефон не нужен: устройство эмулирует фейковый `adb` (`tests/fake_adb.py`),
а экраны рисуются синтетически.

```bash
pip install -r requirements-dev.txt
python -m pytest
```

## Ограничения

- «Зелёная» определяется по оттенку. Бирюзовые и салатовые цвета на границах диапазона можно
  включить или исключить через `hue_min` и `hue_max`.
- Если зелёных кнопок несколько, нажимается самая большая.
- Экраны с `FLAG_SECURE` (банковские приложения и т. п.) отдают чёрный скриншот, и кнопка на
  них не будет найдена.
- Скрипт смотрит только на видимую часть экрана и не прокручивает её.
